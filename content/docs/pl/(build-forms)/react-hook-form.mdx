Przewodnik shadcn dotyczący React Hook Form zaczyna się od Zod. Protoform zachowuje ten sam kształt interfejsu, ale zastępuje
resolver schematu deskryptorem protobuf. React Hook Form pozostaje domyślnym mechanizmem i
wzorcowym zachowaniem dla Protoform.

```bash
bunx shadcn@latest add @protoform/protoform-core
```

```tsx
import { Controller } from "react-hook-form";
import { Button } from "@/components/ui/button";
import { Field, FieldError, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
import { useProtoForm } from "@/hooks/use-proto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  const form = useProtoForm(SignupRequestSchema, {
    defaultValues: { email: "", displayName: "" },
  });

  return (
    <form onSubmit={form.handleSubmit((values) => console.log(form.createMessage(values)))}>
      <Controller
        control={form.control}
        name="email"
        render={({ field, fieldState }) => (
          <Field data-invalid={fieldState.invalid}>
            <FieldLabel htmlFor={field.name}>Email</FieldLabel>
            <Input {...field} id={field.name} aria-invalid={fieldState.invalid} />
            {fieldState.invalid ? <FieldError errors={[fieldState.error]} /> : null}
          </Field>
        )}
      />
      <Button type="submit">Create account</Button>
    </form>
  );
}
```

## Co otrzymujesz

- `resolver: createProtoResolver(schema)` używany wewnętrznie.
- `createMessage(values)` do konwertowania wartości formularza na komunikat protobuf.
- `createUpdateMask()` do uwzględniania w żądaniu aktualizacji wyłącznie zmienionych, zapisywalnych ścieżek protobuf.
- `setOneofValue(path, case, value)` do bezpiecznych aktualizacji pól oneof.
- `setServerErrors(error)` do mapowania naruszeń pól Connect/gRPC z powrotem do RHF.

Zwracana wartość to kompletny obiekt `UseFormReturn`, dzięki czemu istniejące `Controller`, `useFieldArray`,
`watch`, `reset`, opcje resolvera i mniej typowe wzorce React Hook Form pozostają dostępne.

## Walidacja częściowych edycji

Formularze aktualizacji czasem pomijają wartość pola, którą serwer zachowa, na przykład poświadczenie
tylko do zapisu. Włącz walidację `modified-fields`, aby pominięta wartość nie była uznawana za
nieprawidłową, dopóki użytkownik nie edytuje tego pola:

```tsx
const form = useProtoForm(ServiceConnectionSchema, {
  defaultValues: connection,
  validationScope: "modified-fields",
});

const onSubmit = form.handleSubmit(async (values) => {
  await updateConnection(create(UpdateServiceConnectionRequestSchema, {
    connection: form.createMessage(values),
    updateMask: form.createUpdateMask(),
  }));

  form.reset(values);
});
```

Zbiór modyfikacji jest celowo trwały. Jeśli pole początkowo jest puste, otrzyma wartość, a następnie
zostanie ponownie wyczyszczone, Protoform zwaliduje pustą wartość i uwzględni ścieżkę protobuf pola
w masce aktualizacji. Nietknięte puste pole nie jest ani walidowane, ani uwzględniane. `reset()`
rozpoczyna nowy stan bazowy edycji. Błędy CEL na poziomie komunikatu pozostają widoczne, ponieważ
Protoform nie może bezpiecznie przypisać ich do jednego zmodyfikowanego pola. Formularze tworzenia
zachowują domyślną walidację całego komunikatu.

## Generowanie pól

Domyślny element rejestru korzysta z React Hook Form:

```bash
bunx shadcn@latest add @protoform/protoform-react
```

```tsx
import { AutoForm } from "@/components/auto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  return (
    <AutoForm
      schema={SignupRequestSchema}
      formOptions={{ shouldFocusError: true }}
      validationMode="blur"
      revalidationMode="change"
      onFormInit={(form) => {
        // Full React Hook Form API.
        form.watch("email");
      }}
      onSubmit={async (message, form, { updateMask, signal }) => {
        await client.signup(message, { signal });
        console.log(form.formState.isDirty, updateMask?.paths);
      }}
      withSubmit
    />
  );
}
```

`formOptions` jest przekazywane do `useForm`. Funkcje `onFormInit`, `onFieldChange` i `onSubmit` otrzymują
natywną instancję React Hook Form. Protoform dodaje generowane renderowanie bez zastępowania interfejsu API, który
już znasz.

## Eksperymentalne: React Hook Form v8 beta

Obsługa React Hook Form v8 jest osobną, opcjonalną ścieżką. Nie zastępuje ona stabilnych elementów v7
opisanych powyżej, a obie generacje można testować w jednej aplikacji. Adapter jest przypięty do wersji
`8.0.0-beta.3`, dopóki nadrzędny interfejs API pozostaje w fazie beta.

Zainstaluj eksperymentalny natywny hook:

```bash
bunx shadcn@latest add @protoform/use-proto-form-v8
```

```tsx
import { useProtoForm } from "@/hooks/use-proto-form-v8";
```

Oddzielnie zainstaluj eksperymentalny generowany formularz:

```bash
bunx shadcn@latest add @protoform/auto-form-react-hook-form-v8
```

```tsx
import { AutoForm } from "@/components/auto-form-react-hook-form-v8";
```

Te elementy instalują v8 pod aliasem pakietu `react-hook-form-v8` i zachowują natywny interfejs API v8.
Zachowaj oddzielne importy wersji stabilnej i beta do czasu ukończenia migracji. Przed przyjęciem ścieżki
beta zapoznaj się z nadrzędnym
[przewodnikiem migracji z v7 do v8](https://react-hook-form.com/migrate-v7-to-v8) oraz
[uwagami do wydania beta.3](https://github.com/react-hook-form/react-hook-form/releases/tag/v8.0.0-beta.3).

Istotne ograniczenia wersji beta:

- `useFieldArray` udostępnia `field.key` i usuwa `keyName`. Adapter Protoform v8 już używa `key`.
- Płaskie tablice wartości prostych przechodzą sprawdzanie typów w v8, ale bezpośrednie renderowanie
  `useFieldArray` nadal ma ograniczenie w czasie działania. Testy Protoform obejmują dodawanie,
  usuwanie i wysyłanie powtarzanych pól prostych; niestandardowe renderowanie tablic pól sprawdź osobno.
- `Controller` i `useController` przechowują teraz rzeczywisty element DOM. Przekazuj `field.ref`
  do pola, aby zachować obsługę fokusu i natywnej walidacji.
- Używaj `subscribe` zamiast `watch` z wywołaniem zwrotnym. Do zastępowania całej tablicy używaj
  `replace`; planowane usunięcie aktualizacji tablic przez `setValue` nie trafiło jeszcze do beta.3.
