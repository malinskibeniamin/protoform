Użyj testu integracyjnego obejmującego rzeczywisty stos, aby sprawdzić zachowanie formularza należące do Twojej aplikacji. Wyrenderuj formularz,
wejdź z nim w interakcję tak jak użytkownik i prześlij go przez ten sam transport Connect, który jest używany w środowisku produkcyjnym.
Uruchom rzeczywisty router aplikacji na porcie efemerycznym zamiast zastępować wywołania RPC atrapami testowymi.

Ten zakres obejmuje wygenerowany formularz, React Hook Form, Connect Query, serializację HTTP,
procedurę obsługi Connect, Protovalidate oraz mapowanie ustrukturyzowanych błędów pól. Rstest uruchamia komponent w
`happy-dom`, dlatego traktuj ten test jako integracyjny, a nie kompleksowy test end-to-end w przeglądarce.

## Konfiguracja testów

Zainstaluj Rstest i Testing Library w aplikacji:

```bash
bun add --dev @rsbuild/plugin-react @rstest/core happy-dom undici @testing-library/jest-dom @testing-library/react @testing-library/user-event
```

Skonfiguruj zestaw testów integracyjnych z użyciem `happy-dom` i załaduj matchery Testing Library:

```ts title="rstest.integration.config.ts"
import { pluginReact } from "@rsbuild/plugin-react";
import { defineConfig } from "@rstest/core";

export default defineConfig({
  plugins: [pluginReact()],
  setupFiles: ["./rstest.setup.ts"],
  testEnvironment: "happy-dom",
});
```

```ts title="rstest.setup.ts"
import * as jestDomMatchers from "@testing-library/jest-dom/matchers";
import { expect } from "@rstest/core";
import { fetch as nodeFetch } from "undici";

expect.extend(jestDomMatchers);
Object.defineProperty(globalThis, "fetch", {
  configurable: true,
  value: nodeFetch,
});
```

Aplikacja powinna eksportować funkcję budującą serwer, która rejestruje rzeczywiste trasy Connect bez
nasłuchiwania na stałym porcie. Kod uruchamiający środowisko produkcyjne wywołuje `listen()` dla tego serwera, natomiast test zarządza
cyklem życia serwera.

## Test kanoniczny

Wystarczy jeden reprezentatywny formularz. Uwzględnij udane żądanie oraz ustrukturyzowany błąd serwera,
który zostaje przypisany do pola:

```tsx title="profile-form.test.tsx"
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { afterEach, describe, expect, it } from "@rstest/core";

import { buildExampleServer } from "../server/server.js";
import ProfileForm from "./profile-form.js";

let closeServer: (() => Promise<void>) | undefined;

afterEach(async () => {
  await closeServer?.();
  closeServer = undefined;
});

describe("profile form", () => {
  it("submits a generated protobuf message to the Connect server", async () => {
    const server = await buildExampleServer();
    const address = await server.listen({ host: "127.0.0.1", port: 0 });
    closeServer = () => server.close();
    const user = userEvent.setup();

    render(<ProfileForm baseUrl={address} />);

    await user.type(
      screen.getByRole("textbox", { name: /display name/i }),
      "Ada Lovelace"
    );
    await user.type(
      screen.getByRole("textbox", { name: /email/i }),
      "ada@example.com"
    );
    await user.click(screen.getByRole("button", { name: "Submit" }));

    expect(await screen.findByRole("status")).toHaveTextContent(
      "profiles/ada-lovelace"
    );
  });

  it("maps a structured server violation to its field", async () => {
    const server = await buildExampleServer();
    const address = await server.listen({ host: "127.0.0.1", port: 0 });
    closeServer = () => server.close();
    const user = userEvent.setup();

    render(<ProfileForm baseUrl={address} />);

    await user.type(
      screen.getByRole("textbox", { name: /display name/i }),
      "Ada Lovelace"
    );
    const email = screen.getByRole("textbox", { name: /email/i });
    await user.type(email, "ada@blocked.example");
    await user.click(screen.getByRole("button", { name: "Submit" }));

    expect(
      await screen.findByText("Use an email address from an approved domain.")
    ).toBeInTheDocument();
    expect(email).toHaveAttribute("aria-invalid", "true");
  });
});
```

`port: 0` powoduje, że system operacyjny przydziela dostępny port, dzięki czemu równolegle działające procesy robocze nie rywalizują o
wspólny adres. `afterEach` zamyka serwer nawet wtedy, gdy asercja zakończy się niepowodzeniem. `findByRole` czeka na
wynik asynchronicznej mutacji bez stosowania opóźnień czasowych.

W katalogu roboczym Protoform uruchom bezpośrednio wybrany test:

```bash
bun run test:integration -- examples/basic/basic-form.test.tsx
```

Kompletny przykład z repozytorium znajduje się w
[`examples/basic/basic-form.test.tsx`](https://github.com/malinskibeniamin/protoform/blob/main/examples/basic/basic-form.test.tsx).

## Zachowaj ukierunkowany zakres zestawu testów

Testuj zachowania należące do aplikacji:

- reprezentatywne udane przesłanie formularza
- reguły biznesowe zwracające ustrukturyzowane błędy pól
- interfejs odzyskiwania po błędzie specyficzny dla aplikacji, jeśli różni się od formularza kanonicznego

Nie sprawdzaj każdego wygenerowanego pola, wewnętrznego stanu React, szczegółów implementacji transportu ani każdego
przykładowego formularza. Zestaw testów zgodności Protoform obejmuje wielokrotnego użytku kontrakty deskryptorów, walidacji, konwersji
i mapowania ścieżek. Dodaj kolejny test integracyjny aplikacji tylko wtedy, gdy formularz wprowadza
inny przepływ przesyłania lub odzyskiwania po błędzie.

Użyj Playwright osobno, gdy testowane ryzyko dotyczy układu w przeglądarce, obsługi fokusu, natywnych kontrolek lub kompletnej
ścieżki użytkownika we wdrożonej aplikacji.
