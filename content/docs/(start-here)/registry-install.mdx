title: Registry install
description: "Install Protoform registry items with shadcn, verify their dependencies, and start building protobuf-backed forms in an existing React app."
---

Protoform is distributed as a shadcn-style custom registry. You can install the full stack or choose a smaller entry point.

## 1. Add the registry namespace

```json title="components.json"
{
  "registries": {
    "@protoform": "https://raw.githubusercontent.com/malinskibeniamin/protoform/v1.0.0/public/r/{name}.json"
  }
}
```

Keep the Git tag pinned and retain the `/r/{name}.json` path so shadcn can resolve each
`@protoform` item.

## 2. Pick an install target

The registry copies all Protoform source into your app and installs only public third-party
dependencies. No Protoform npm registry or package token is required.

```bash
# Hook only: React Hook Form + ProtoValidate + server error mapping
bunx shadcn@latest add @protoform/protoform-core

# AutoForm renderer: uses your components.json ui alias
bunx shadcn@latest add @protoform/protoform-react

# Optional default shadcn UI implementations for greenfield apps
bunx shadcn@latest add @protoform/protoform-shadcn

# Experimental React Hook Form v8 beta hook
bunx shadcn@latest add @protoform/use-proto-form-v8

# Experimental React Hook Form v8 beta AutoForm
bunx shadcn@latest add @protoform/auto-form-react-hook-form-v8

# Native TanStack Form hook
bunx shadcn@latest add @protoform/use-proto-form-tanstack

# TanStack Form AutoForm
bunx shadcn@latest add @protoform/auto-form-tanstack

# Experimental TanStack Form v2 alpha hook
bunx shadcn@latest add @protoform/use-proto-form-tanstack-v2

# Experimental TanStack Form v2 alpha AutoForm
bunx shadcn@latest add @protoform/auto-form-tanstack-v2

# Default React Hook Form stack
bunx shadcn@latest add @protoform/protoform

# Demos and generated example schemas
bunx shadcn@latest add @protoform/protoform-examples

# Complete five-RPC bookstore
bunx shadcn@latest add @protoform/bookstore
```

## Registry layers

| Item | Use when | Includes |
| --- | --- | --- |
| `hook-runtime` | You are maintaining a form hook adapter | Focused protobuf conversion, validation, field-mask, and Connect error internals |
| `protoform-core` | You already have a shadcn form UI and want protobuf validation | `useProtoForm`, ProtoValidate resolver, oneof helpers, Connect/gRPC error mapping |
| `protobuf-provider` | You need AutoForm schema parsing or AIP workflows | Complete schema/UI parser, annotations, AIP metadata, and workflows |
| `use-proto-form-v8` | You are evaluating React Hook Form v8 beta | Separate v8-native hook pinned to `8.0.0-beta.3` |
| `use-proto-form-tanstack` | You already use TanStack Form | Native TanStack API plus protobuf messages, update masks, oneofs, and server errors |
| `protoform-react` | You want schema-generated fields with the default engine | Shared renderer plus the React Hook Form adapter |
| `protoform-shadcn` | You want greenfield UI defaults | `protoform-react` plus optional shadcn implementations installed under `components/ui` |
| `auto-form-react-hook-form-v8` | You are evaluating generated fields on React Hook Form v8 beta | Separate v8-native AutoForm adapter and shared renderer |
| `auto-form-tanstack` | You want schema-generated fields with TanStack Form | Shared renderer plus the TanStack Form adapter |
| `use-proto-form-tanstack-v2` | You are evaluating TanStack Form v2 alpha | Separate v2-native hook pinned to `2.0.0-alpha.2` |
| `auto-form-tanstack-v2` | You are evaluating generated fields on TanStack Form v2 alpha | Separate v2-native AutoForm adapter and shared renderer |
| `auto-form-core` | You are maintaining an engine adapter | Engine-neutral renderer installed by both AutoForm items |
| `protoform` | You want the default product surface | Core, React renderer, and default shadcn UI implementations |
| `protoform-examples` | You want reference demos | generated example schemas and demo components |
| `bookstore` | You want one complete RPC story | five methods, generated bindings, forms, and the temporary service |

## Why split it?

`protoform-core` composes `useProtoForm` with the focused `hook-runtime`, without UI imports,
schema/UI metadata parsing, or Protoform's generated validation/UI descriptor modules. Install `protobuf-provider` for the complete protobuf API and
`protoform-examples` for generated fixtures and demos.
`protoform-react` adds AutoForm rendering and field logic, resolving its UI capabilities through the
`ui` alias in `components.json`. Mature applications can point that alias at a canonical
`components/ui/*` facade made of direct re-exports or thin compatibility adapters.

`protoform-shadcn` is the optional default implementation for greenfield applications. It installs
the UI modules under `components/ui` without making them part of the React renderer. Per-form
`AutoFormUIComponents` overrides remain focused on the form, field wrappers, submit button,
collection wrappers, and errors rather than injecting every primitive at runtime.

## Pin a source snapshot

The hosted registry contains current source. For a reproducible install, pin the namespace to a Git
tag:

```json title="components.json"
{
  "registries": {
    "@protoform": "https://raw.githubusercontent.com/malinskibeniamin/protoform/v1.0.0/public/r/{name}.json"
  }
}
```

```bash
bunx shadcn@latest add @protoform/protoform
```

Updating is explicit: run `shadcn add` again, review the source diff, and keep or adapt the changes.
