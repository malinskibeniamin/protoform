shadcn React Hook Form 指南以 Zod 為起點。Protoform 保留相同的 UI 結構，但以 protobuf 描述元取代
schema resolver。React Hook Form 仍是預設引擎，也是 Protoform 的參考行為。

```bash
bunx shadcn@latest add @protoform/use-proto-form
```

```tsx
import { Controller } from "react-hook-form";
import { Button } from "@/components/ui/button";
import { Field, FieldError, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
import { useProtoForm } from "@/hooks/use-proto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  const form = useProtoForm(SignupRequestSchema, {
    defaultValues: { email: "", displayName: "" },
  });

  return (
    <form onSubmit={form.handleSubmit((values) => console.log(form.createMessage(values)))}>
      <Controller
        control={form.control}
        name="email"
        render={({ field, fieldState }) => (
          <Field data-invalid={fieldState.invalid}>
            <FieldLabel htmlFor={field.name}>Email</FieldLabel>
            <Input {...field} id={field.name} aria-invalid={fieldState.invalid} />
            {fieldState.invalid ? <FieldError errors={[fieldState.error]} /> : null}
          </Field>
        )}
      />
      <Button type="submit">Create account</Button>
    </form>
  );
}
```

## 可獲得的功能

- 底層使用 `resolver: createProtoResolver(schema)`。
- 使用 `createMessage(values)` 將表單值轉換為 protobuf 訊息。
- 使用 `createUpdateMask()`，在更新請求中僅包含已修改且可寫入的 protobuf 路徑。
- 使用 `setOneofValue(path, case, value)` 安全地更新 oneof。
- 使用 `setServerErrors(error)` 將 Connect/gRPC 欄位違規對應回 RHF。

回傳值是完整的 `UseFormReturn`，因此仍可使用既有的 `Controller`、`useFieldArray`、
`watch`、`reset`、resolver 選項，以及較少見的 React Hook Form 模式。

## 產生欄位

預設的 registry 項目使用 React Hook Form：

```bash
bunx shadcn@latest add @protoform/auto-form
```

```tsx
import { AutoForm } from "@/components/auto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  return (
    <AutoForm
      schema={SignupRequestSchema}
      formOptions={{ shouldFocusError: true }}
      validationMode="blur"
      revalidationMode="change"
      onFormInit={(form) => {
        // Full React Hook Form API.
        form.watch("email");
      }}
      onSubmit={async (message, form, { updateMask, signal }) => {
        await client.signup(message, { signal });
        console.log(form.formState.isDirty, updateMask?.paths);
      }}
      withSubmit
    />
  );
}
```

`formOptions` 會傳遞給 `useForm`。`onFormInit`、`onFieldChange` 和 `onSubmit` 會接收
原生 React Hook Form 實例。Protoform 加入產生式渲染，同時保留你已熟悉的 API。

## 實驗性功能：React Hook Form v8 beta

React Hook Form v8 支援是獨立且須選擇啟用的途徑。它不會取代上述穩定版 v7 項目，
且可在同一個應用程式中評估這兩個世代。上游 API 仍處於 beta 階段，因此介接器固定使用
`8.0.0-beta.3`。

安裝實驗性的原生 hook：

```bash
bunx shadcn@latest add @protoform/use-proto-form-v8
```

```tsx
import { useProtoForm } from "@/hooks/use-proto-form-v8";
```

另外安裝實驗性的產生式表單：

```bash
bunx shadcn@latest add @protoform/auto-form-react-hook-form-v8
```

```tsx
import { AutoForm } from "@/components/auto-form-react-hook-form-v8";
```

這些項目會在 `react-hook-form-v8` 套件別名下安裝 v8、保留原生 v8 API，並
使用 v8 的 `key` 欄位陣列識別碼。在遷移完成前，請將穩定版與 beta 版的 import 分開。採用 beta 途徑前，請先檢閱上游的
[v8 beta 版本資訊](https://github.com/react-hook-form/react-hook-form/releases/tag/v8.0.0-beta.0)。

已標準化採用其他表單儲存庫？請參閱
[TanStack Form](/docs/tanstack-form) 中的原生 hook 與產生式 AutoForm 使用方式，或
[Formik](/docs/formik) 和 [Final Form](/docs/final-form) 介接器。
