## 新增內容

- `(google.api.resource)` 描述元。
- `IDENTIFIER`、`IMMUTABLE` 和 `OUTPUT_ONLY` 欄位行為。
- 根據已變更的可寫入欄位，自動建立 snake-case 更新遮罩。

## 合約

```proto
message MaskableProfile {
  option (google.api.resource) = {
    type: "protoform.example.com/Profile"
    pattern: "profiles/{profile}"
  };

  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  string display_name = 2;
  string biography = 3;
  string home_region = 4 [(google.api.field_behavior) = IMMUTABLE];
  string lifecycle_state = 5 [(google.api.field_behavior) = OUTPUT_ONLY];
}
```

<AutoForm

## 驗證示範的步驟

1. 對照 `protobuf schema`、產生的 `descriptor`、`field config` 與 `registry item`，確認 欄位 名稱、presence 語意、預設值 和 oneof 分支 保持 一致。
2. 依序 嘗試 正常 輸入、邊界 輸入、空值、重複 項目 和 無效 格式，確認 用戶端 驗證 顯示 所有 可操作 錯誤。
3. 切換 oneof 分支、刪除 巢狀 訊息、編輯 repeated message 和 map value，確認 舊分支 資料 不會 在提交時 恢復。
4. 檢查 鍵盤 導覽、焦點 順序、ARIA 屬性、錯誤 摘要 與 提交 狀態，確保 輔助 技術 能夠 理解 每個 控制項。
5. 比較 提交 前後的 protobuf message，確認 已知 欄位 正確 更新，未知 wire 欄位 在未修改的 巢狀 結構 中 保留。
6. 最後 執行 registry 安裝、型別 檢查、單元 測試 與 整合 測試，再把 相同 契約 用於 真實 應用程式。
