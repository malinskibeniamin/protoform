## 新增內容

- 包含兩個純量分支的必填 `oneof`。
- 提交的訊息中僅有一個具型別的作用中分支。
- 所選分支變更時自動清除資料。

## 合約

```proto
message OneofForm {
  oneof contact {
    option (buf.validate.oneof).required = true;
    option (protoform.v1.oneof_ui).description = "Choose one contact method.";

    string email = 1;
    string phone = 2;
  }
}
```

輸入電子郵件、切換至「電話」，然後提交。具型別的訊息只包含電話分支；隱藏的電子郵件會被清除，而不會成為幽靈資料。

## 驗證示範的步驟

1. 對照 `protobuf schema`、產生的 `descriptor`、`field config` 與 `registry item`，確認 欄位 名稱、presence 語意、預設值 和 oneof 分支 保持 一致。
2. 依序 嘗試 正常 輸入、邊界 輸入、空值、重複 項目 和 無效 格式，確認 用戶端 驗證 顯示 所有 可操作 錯誤。
3. 切換 oneof 分支、刪除 巢狀 訊息、編輯 repeated message 和 map value，確認 舊分支 資料 不會 在提交時 恢復。
4. 檢查 鍵盤 導覽、焦點 順序、ARIA 屬性、錯誤 摘要 與 提交 狀態，確保 輔助 技術 能夠 理解 每個 控制項。
5. 比較 提交 前後的 protobuf message，確認 已知 欄位 正確 更新，未知 wire 欄位 在未修改的 巢狀 結構 中 保留。
6. 最後 執行 registry 安裝、型別 檢查、單元 測試 與 整合 測試，再把 相同 契約 用於 真實 應用程式。
