**正式環境就緒概況 v2** 將 Protoform 的支援聲明轉換為具版本控管、機器可讀的能力清冊。涵蓋與表單相關的 Protobuf 功能、目前所有 Protovalidate 規則系列、CEL 行為、與表單相關的 Google AIP 指引，以及正式環境執行品質。

此目錄以目前的 [Protobuf 語言指南](https://protobuf.dev/programming-guides/)、[Protovalidate 標準規則](https://buf.build/docs/reference/protovalidate/rules/)、[CEL 語言概覽](https://cel.dev/overview/cel-overview)及[一般 AIP 目錄](https://google.aip.dev/general)為依據。此概況將這些廣泛的規格限縮至 TypeScript 表單函式庫可負責的行為，並明確列出排除的責任。

目前 Profile v2 分數為 **100%：174 項適用檢查中有 174 項已驗證**。另有 16 項排除的檢查仍會顯示，但不影響百分比：13 項外部責任、1 項已驗證的選用功能、1 項不在目標範圍，以及 1 項已取代。因此，依此概況的嚴格定義，Protoform **已可用於正式環境**。維護中的 Protobuf-ES v1 橋接層已驗證為選用的遷移支援，但不屬於此聲明；標準執行階段目標為 Protobuf-ES v2。

## 百分比的意義

整體百分比為 `verified / applicable`：

- **已驗證**需要自動化證據：此儲存庫中實際存在的測試檔案與測試名稱。
- **缺口**是目前承諾提供但缺少充分自動化證據的適用行為。
- **已延後**是刻意排定於此版本之後處理的適用行為。它會降低就緒程度，並列出下一個測試。
- **不支援**是 Protoform 目前未處理的適用上游行為。它會降低就緒程度，並列出下一個測試。
- **選用**是有證據支持的附加或遷移能力，不納入標準分母。
- **不在目標範圍**是 Protoform 在此概況中明確不承諾支援的目前上游行為。
- **外部責任**由後端、傳輸執行階段或治理流程負責，不納入分母。
- **已取代**已由上游移除或替換，不納入分母。
- **必要概況**標示不可妥協的子集。

`Production ready: yes` 要求每項適用檢查均已驗證，且所參照的測試套件皆通過。僅有文件、實作程式碼或人工聲明無法提高分數。若已驗證的資料列指向不存在的測試，證據完整性測試也會失敗。

發布閘門的範圍比正式環境就緒聲明更窄。當沒有未規劃的 `missing` 資料列，且所有已驗證的證據參照仍有效時，即可通過。經核准的已延後及不支援資料列仍會顯示並降低就緒程度，但不會導致目前的每個建置都失敗。發布閘門通過不得解讀為 `Production ready: yes`。

這可避免「支援 Protobuf」之類的廣泛聲明掩蓋未經測試的純量系列、存在性語意、知名型別、驗證運算子或錯誤路徑行為。

## 執行報告

```bash
bun run readiness:report
```

以 JSON 取得完整概況，供其他儀表板或 CI 成品使用：

```bash
bun run readiness:report -- --json
```

執行與 CI 相同的發布閘門：

```bash
bun run readiness:gate
```

CI 會在一致性測試套件後執行 `readiness:gate`。當概況中出現未規劃的缺口時，會以非零狀態碼結束。證據完整性測試會另外拒絕不存在的證據檔案或測試名稱。

對目標分支執行相同的 AIP-180 相容性檢查：

```bash
bun run proto:breaking -- --against '.git#ref=origin/main'
```

此檢查對穩定的 protobuf 模組使用 Buf 的 `FILE` 原則。精確的允許清單項目會保留先前核准的 1.0 前檔案移動與列舉移除；不會停用任何規則類別，其他所有相容性違規都會導致失敗。CI 會將提取要求與其基礎提交進行比較，並將 main 的推送與前一個提交進行比較。隔離的預期失敗測試資料可證明欄位型別變更會遭拒絕。

在本機驗證公開的原始碼複製發行版：

```bash
bun run registry:build
bun run registry:consumer-smoke
```

此流程會提供建置完成的 registry，將 bookstore 與兩個表單引擎安裝至乾淨的消費端環境，並僅對複製的原始碼與公開的第三方相依套件執行型別檢查。

## Profile v2 的範圍

分母採明確定義，而非假設所有 Protobuf 或 AIP 功能都應屬於表單函式庫：

| 領域 | 已驗證 | 適用的待處理工作 | 已排除 |
| --- | --- | --- | --- |
| Protobuf | 標準 v2 行為、Editions 2023 描述元、未知欄位保留，以及服務/RPC 工作流程分類 | 無 | 維護中的 Protobuf-ES v1 橋接層是已驗證的選用功能；擴充功能與已棄用的群組探索不在目標範圍；二進位編解碼器相容性仍由 Protobuf-ES 負責 |
| Protovalidate | 必要/忽略行為，以及目前所有純量、集合、知名型別、範例與預定義規則系列 | 無 | 已移除的 `disabled`/`skip` 選項已由目前的忽略語意取代 |
| CEL | 欄位/訊息結果、巢狀路徑、多項違規、部分未知值、成本限制、失敗，以及 UI 運算式 | 無 | 後端授權與原則強制執行仍由伺服器負責 |
| AIP | 資源中繼資料、標準要求形態、轉碼角色、方法分類、長時間執行作業、工作/匯入/匯出工作流程、數量與標準化代碼欄位、範圍、部分結果、重試、原則預覽、遮罩、etag、結構化錯誤，以及相容性強制執行 | 無 | AIP 治理、發布審查、授權強制執行，以及儲存庫所有權 |
| 正式環境執行階段 | 表單框架整合、產生的表單、步驟式表單、無障礙功能、韌性、瀏覽器、相容性、安全性及效能 | 無 | 無 |

執行階段證據包括代表性表單狀態的 axe 檢查、僅使用鍵盤的步驟復原、Chromium/Firefox/WebKit 設定、窄視窗溢位檢查、所有文件範例的 hydration 檢查、可中止的驗證與提交、50/200/500 欄位預算、套件大小與 tree-shaking 預算、僅透過 registry 的消費端安裝，以及格式錯誤輸入/HTML 注入案例。

此概況刻意採用細粒度設計。表格驅動測試可驗證單一能力中的多個值，但單一廣泛的整合測試不能將不相關的功能系列標示為完成。

## 如何維持 100%

Profile v2 會計入由用戶端負責的已延後及不支援工作，而不以寬泛的不適用標籤隱藏。後續工作應深化證據，而不削弱分母：

- **深化證據，而非只用布林值。** 為每項能力要求相關的單元、一致性、瀏覽器及隔離消費端證據組合。記錄上游規格版本與證據的新鮮度，不允許單一測試參照涵蓋所有信心水準。
- **消費端部署矩陣。** 將套件與 registry 輸出安裝至全新的 Vite 及伺服器端算繪 React 應用程式，接著驗證正式環境建置、hydration、用戶端邊界，以及支援的 React 與框架版本。
- **結構描述演進與草稿。** 將新的頂層未知欄位保留機制擴充至巢狀編輯，接著涵蓋重新命名、移動及移除的欄位、未知列舉值、版本差異，以及分階段的 v1 橋接升級，且不得發生無提示的資料遺失。
- **安全性與防誤用能力。** 為格式錯誤的描述元、深層巢狀輸入、過大集合、CEL 預算耗盡、機密洩漏及套件來源新增屬性測試與模糊測試。
- **網路生命週期與可操作性。** 將已驗證的重試及長時間執行作業核心擴充至離線復原、重新連線風暴、跨分頁取消，以及已遮蔽敏感資訊的遙測掛鉤。
- **人工無障礙驗證。** 分別追蹤螢幕閱讀器檢查、400% 縮放、強制色彩、減少動態效果及觸控目標。人工證據仍會顯示，但不會提高自動化就緒百分比。
- **進階表單使用體驗。** 測試遠端選項載入、在地化值與訊息、草稿自動儲存、大型重複欄位虛擬化，以及跨步驟非同步相依性。

## 新增或完成檢查

1. 為該能力新增最小範圍且會失敗的一致性或執行階段測試。
2. 實作該行為，並使聚焦測試通過。
3. 將 `readiness/profile.ts` 中對應的資料列從 `missing`、`deferred` 或 `unsupported` 改為 `verified`，並指向該測試。
4. 執行 `bun run test:conformance`、負責該功能的測試套件，以及 `bun run readiness:report`。
5. 當上游規格新增與表單相關的功能時，重新檢視分母。

Profile 變更應比照公開相容性變更進行審查：能力 ID 保持穩定、明確加入新需求，且移除項目時必須記錄範圍決策。
