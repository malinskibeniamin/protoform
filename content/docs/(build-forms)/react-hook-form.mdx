The shadcn React Hook Form guide starts with Zod. Protoform keeps the same UI shape, but replaces
the schema resolver with a protobuf descriptor. React Hook Form remains the default engine and the
reference behavior for Protoform.

```bash
bunx shadcn@latest add @protoform/use-proto-form
```

```tsx
import { Controller } from "react-hook-form";
import { Button } from "@/components/ui/button";
import { Field, FieldError, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
import { useProtoForm } from "@/hooks/use-proto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  const form = useProtoForm(SignupRequestSchema, {
    defaultValues: { email: "", displayName: "" },
  });

  return (
    <form onSubmit={form.handleSubmit((values) => console.log(form.createMessage(values)))}>
      <Controller
        control={form.control}
        name="email"
        render={({ field, fieldState }) => (
          <Field data-invalid={fieldState.invalid}>
            <FieldLabel htmlFor={field.name}>Email</FieldLabel>
            <Input {...field} id={field.name} aria-invalid={fieldState.invalid} />
            {fieldState.invalid ? <FieldError errors={[fieldState.error]} /> : null}
          </Field>
        )}
      />
      <Button type="submit">Create account</Button>
    </form>
  );
}
```

## What you get

- `resolver: createProtoResolver(schema)` under the hood.
- `createMessage(values)` to convert form values into a protobuf message.
- `createUpdateMask()` to include only changed, writable protobuf paths in an update request.
- `setOneofValue(path, case, value)` for oneof-safe updates.
- `setServerErrors(error)` to map Connect/gRPC field violations back into RHF.

The return value is the complete `UseFormReturn`, so existing `Controller`, `useFieldArray`,
`watch`, `reset`, resolver options, and uncommon React Hook Form patterns remain available.

## Validate partial edits

Update forms sometimes omit a field value that the server will retain, such as a write-only
credential. Opt into `modified-fields` validation so the omitted value is not treated as invalid
until the user edits that field:

```tsx
const form = useProtoForm(ServiceConnectionSchema, {
  defaultValues: connection,
  validationScope: "modified-fields",
});

const onSubmit = form.handleSubmit(async (values) => {
  await updateConnection(create(UpdateServiceConnectionRequestSchema, {
    connection: form.createMessage(values),
    updateMask: form.createUpdateMask(),
  }));

  form.reset(values);
});
```

The modification set is intentionally sticky. If a field starts blank, receives input, then is
cleared again, Protoform validates the blank value and includes its protobuf path in the update
mask. An untouched blank field is neither validated nor included. `reset()` starts a new edit
baseline. Message-level CEL issues remain visible because Protoform cannot safely attribute them to
one modified field. Create forms keep the default full-message validation.

## Generate the fields

The default registry item uses React Hook Form:

```bash
bunx shadcn@latest add @protoform/auto-form
```

```tsx
import { AutoForm } from "@/components/auto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  return (
    <AutoForm
      schema={SignupRequestSchema}
      formOptions={{ shouldFocusError: true }}
      validationMode="blur"
      revalidationMode="change"
      onFormInit={(form) => {
        // Full React Hook Form API.
        form.watch("email");
      }}
      onSubmit={async (message, form, { updateMask, signal }) => {
        await client.signup(message, { signal });
        console.log(form.formState.isDirty, updateMask?.paths);
      }}
      withSubmit
    />
  );
}
```

`formOptions` is passed to `useForm`. `onFormInit`, `onFieldChange`, and `onSubmit` receive the
native React Hook Form instance. Protoform adds generated rendering without replacing the API you
already know.

## Experimental: React Hook Form v8 beta

React Hook Form v8 support is a separate, opt-in path. It does not replace the stable v7 items
above, and both generations can be evaluated in one application. The adapter is pinned to
`8.0.0-beta.3` while the upstream API remains in beta.

Install the experimental native hook:

```bash
bunx shadcn@latest add @protoform/use-proto-form-v8
```

```tsx
import { useProtoForm } from "@/hooks/use-proto-form-v8";
```

Install the experimental generated form separately:

```bash
bunx shadcn@latest add @protoform/auto-form-react-hook-form-v8
```

```tsx
import { AutoForm } from "@/components/auto-form-react-hook-form-v8";
```

These items install v8 under the `react-hook-form-v8` package alias and keep the native v8 API.
Keep the stable and beta imports separate until the migration is complete. Check the upstream
[v7 to v8 migration guide](https://react-hook-form.com/migrate-v7-to-v8) and
[beta.3 release notes](https://github.com/react-hook-form/react-hook-form/releases/tag/v8.0.0-beta.3)
before adopting the beta path.

Relevant beta caveats:

- `useFieldArray` exposes `field.key` and removes `keyName`. The Protoform v8 adapter already
  uses `key`.
- Flat primitive arrays type-check in v8, but direct `useFieldArray` rendering still has an
  upstream runtime limitation. Protoform tests append, remove, and submit behavior for repeated
  primitive fields; verify custom field-array rendering separately.
- `Controller` and `useController` now retain the real DOM element. Forward `field.ref` to the
  input so focus and native validation continue to work.
- Prefer `subscribe` over callback `watch`. Prefer `replace` for whole field arrays; the planned
  removal of array updates through `setValue` has not shipped in beta.3.

Already standardized on another form store? See the native hook and generated AutoForm path in
[TanStack Form](/docs/tanstack-form), or the
[Formik](/docs/formik) and [Final Form](/docs/final-form) adapters.
