**第 2 级，共 8 级**

**前置要求：** [基础表单](/docs/bare-bones-form)

此示例保持字段简单，仅改变呈现方式。每个步骤包含一个字符串字段；“返回”和“继续”会保留同一份表单状态。

## 新增内容

- protobuf 字段元数据中的稳定步骤 ID。
- 包含两项的 React 步骤配置。
- 垂直进度轨道；在窄屏幕上，它会移至表单上方。
- 支持无障碍访问的线性导航，包含`第 X 步，共 Y 步`、“返回”和“继续”。
- 一次类型安全的提交，其中包含两个步骤的值。

## 契约

```proto
message TwoStepForm {
  string name = 1 [(protoform.v1.field_ui).step = "name"];
  string email = 2 [(protoform.v1.field_ui).step = "contact"];
}
```

## React

```tsx
const steps = [
  { id: "name", title: "Name" },
  { id: "contact", title: "Contact" },
]

<AutoForm<TwoStepForm>
  schema={TwoStepFormSchema}
  stepper={{ orientation: "vertical", steps }}
  withSubmit
/>
```

有序步骤仍是由 React 管理的呈现配置。描述符仅将每个字段分配给一个稳定的步骤 ID。

## 验证演示的步骤

1. 对照 `protobuf schema`、生成的 `descriptor`、`field config` 与 `registry item`，确认 字段 名称、presence 语义、默认值 和 oneof 分支 保持 一致。
2. 依次 尝试 正常 输入、边界 输入、空值、重复 项目 和 无效 格式，确认 客户端 校验 展示 所有 可操作 错误。
3. 切换 oneof 分支、删除 嵌套 消息、编辑 repeated message 和 map value，确认 旧分支 数据 不会 在提交时 恢复。
4. 检查 键盘 导航、焦点 顺序、ARIA 属性、错误 摘要 与 提交 状态，确保 辅助 技术 能够 理解 每个 控件。
5. 对比 提交 前后的 protobuf message，确认 已知 字段 正确 更新，未知 wire 字段 在未修改的 嵌套 结构 中 保留。
6. 最后 运行 registry 安装、类型 检查、单元 测试 与 集成 测试，再把 相同 契约 用于 真实 应用。
