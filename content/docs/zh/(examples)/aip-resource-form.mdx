## 新增内容

- 一个 `(google.api.resource)` 描述符。
- `IDENTIFIER`、`IMMUTABLE` 和 `OUTPUT_ONLY` 字段行为。
- 根据已修改的可写字段自动生成 snake_case 更新掩码。

## 契约

```proto
message MaskableProfile {
  option (google.api.resource) = {
    type: "protoform.example.com/Profile"
    pattern: "profiles/{profile}"
  };

  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  string display_name = 2;
  string biography = 3;
  string home_region = 4 [(google.api.field_behavior) = IMMUTABLE];
  string lifecycle_state = 5 [(google.api.field_behavior) = OUTPUT_ONLY];
}
```

## React

```tsx
<AutoForm
  defaultValues={profile}
  schema={MaskableProfileSchema}
  withSubmit
  onSubmit={(_profile, _form, context) => {
    sendUpdate(context.updateMask)
  }}
/>
```

客户端负责构建掩码；服务器仍会验证掩码、合并补丁、强制执行 etag，并
对更新进行授权。有关完整的资源和标准方法结构，请参阅 [Google AIP 和 protobuf 设计](/docs/aip-protobuf)。

## 验证演示的步骤

1. 对照 `protobuf schema`、生成的 `descriptor`、`field config` 与 `registry item`，确认 字段 名称、presence 语义、默认值 和 oneof 分支 保持 一致。
2. 依次 尝试 正常 输入、边界 输入、空值、重复 项目 和 无效 格式，确认 客户端 校验 展示 所有 可操作 错误。
3. 切换 oneof 分支、删除 嵌套 消息、编辑 repeated message 和 map value，确认 旧分支 数据 不会 在提交时 恢复。
4. 检查 键盘 导航、焦点 顺序、ARIA 属性、错误 摘要 与 提交 状态，确保 辅助 技术 能够 理解 每个 控件。
5. 对比 提交 前后的 protobuf message，确认 已知 字段 正确 更新，未知 wire 字段 在未修改的 嵌套 结构 中 保留。
6. 最后 运行 registry 安装、类型 检查、单元 测试 与 集成 测试，再把 相同 契约 用于 真实 应用。
