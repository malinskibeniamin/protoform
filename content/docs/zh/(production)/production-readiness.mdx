能力证据概况 v3 将 Protoform 的支持声明转化为版本化、机器可读的能力清单。它涵盖与表单相关的 Protobuf 功能、当前所有 Protovalidate 规则系列、CEL 行为、与表单相关的 Google AIP 指南以及运行时质量。

该目录以当前的 [Protobuf 语言指南](https://protobuf.dev/programming-guides/)、[Protovalidate 标准规则](https://buf.build/docs/reference/protovalidate/rules/)、[CEL 语言概述](https://cel.dev/overview/cel-overview)和[通用 AIP 目录](https://google.aip.dev/general)为依据。该概况将这些宽泛规范收窄到 TypeScript 表单库可以负责的行为，并明确展示不在范围内的责任。

当前 Profile v3 已完整：175 项适用检查中的 175 项都有证据。另有 16 项排除检查保持可见，但不影响百分比：13 项外部检查、1 项已验证可选检查、1 项不在目标范围内的检查和 1 项已被取代的检查。概况完整不代表生产就绪认证，也不能证明当前检出版本已通过发布验证。维护中的 Protobuf-ES v1 桥接已验证为可选迁移支持；规范运行时目标是 Protobuf-ES v2。

## 百分比的含义

总体百分比为 `verified / applicable`：

- **已验证**要求提供自动化证据：此代码仓库中实际存在的测试文件和测试名称。
- **缺口**是当前承诺的适用行为，但缺少充分的自动化证据。
- **已推迟**是有意安排在此版本之后实现的适用行为。它会降低就绪度，并注明下一项测试。
- **不支持**是 Protoform 当前无法处理的适用上游行为。它会降低就绪度，并注明下一项测试。
- **可选**是有证据支持的附加或迁移能力，不计入规范分母。
- **不在目标范围内**是 Protoform 在此概况中明确不承诺的当前上游行为。
- **外部**由后端、传输运行时或治理流程负责，不计入分母。
- **已被取代**已在上游移除或替换，不计入分母。
- **必需概况**突出显示不可妥协的子集。

`Profile complete: yes` 表示每个适用行都标记为已验证。仅凭文档、实现代码或人工声明无法提高得分。如果已验证行指向不存在的测试，证据完整性测试也会失败。该概况不会运行这些测试套件，也不会认证部署、运维、安全或发布就绪度。

这可防止“支持 Protobuf”之类的宽泛声明掩盖未经测试的标量系列、存在性语义、知名类型、验证运算符或错误路径行为。

## 运行报告

```bash
bun run readiness:report
```

获取 JSON 格式的完整概况，供其他仪表板或 CI 构件使用：

```bash
bun run readiness:report -- --json
```

仅检查概况完整性：

```bash
bun run readiness:gate
```

当适用行处于 missing、deferred 或 unsupported 状态时，`readiness:gate` 会以非零状态退出。它是概况门禁，不是发布门禁。完整的本地发布验证需单独运行：

```bash
bun run release:gate
```

`release:gate` 会运行完整质量门禁，包括一致性、单元、集成、浏览器和端到端测试、构建、使用方冒烟测试、类型检查与 lint。

针对目标分支运行相同的 AIP-180 兼容性检查：

```bash
bun run proto:breaking -- --against '.git#ref=origin/main'
```

该检查对稳定的 protobuf 模块使用 Buf 的 `FILE` 策略。精确的允许列表条目保留了此前获批的 1.0 前文件移动和枚举移除；不会禁用任何规则类别，其他所有兼容性违规都会导致失败。CI 将拉取请求与其基础提交进行比较，并将 main 分支推送与前一个提交进行比较。隔离的预期失败固件可证明字段类型变更会被拒绝。

在本地验证公开源码复制分发：

```bash
bun run registry:build
bun run registry:consumer-smoke
```

这会提供已构建的 registry，将 bookstore 和两个表单引擎安装到干净的使用方环境中，并仅对复制的源码和公开的第三方依赖项执行类型检查。

## Profile v3 的范围

分母经过明确界定，不会假装所有 Protobuf 或 AIP 功能都属于表单库：

| 领域 | 已验证 | 适用的未完成工作 | 已排除 |
| --- | --- | --- | --- |
| Protobuf | 规范 v2 行为、Editions 2023 和 2024 描述符、严格符号可见性、仅选项导入、未知字段保留以及服务/RPC 工作流分类 | 无 | 维护中的 Protobuf-ES v1 桥接是已验证的可选能力；扩展和弃用的 group 发现不在目标范围内；二进制编解码器兼容性仍由 Protobuf-ES 负责 |
| Protovalidate | Required/ignore 行为以及当前所有标量、集合、知名类型、示例和预定义规则系列 | 无 | 已移除的 `disabled`/`skip` 选项已被当前的 ignore 语义取代 |
| CEL | 字段/消息结果、嵌套路径、多项违规、部分未知值、成本限制、失败和 UI 表达式 | 无 | 后端授权和策略执行仍由服务器负责 |
| AIP 感知客户端覆盖 | 资源元数据、标准请求结构、转码角色、方法分类、长时间运行操作、任务/导入/导出工作流、数量和标准化代码字段、范围、部分结果、重试、策略预览、掩码、etag、结构化错误以及兼容性执行 | 无 | 服务器与组织一致性、AIP 治理、发布审核、授权执行和代码仓库所有权 |
| 生产运行时 | 表单框架集成、生成式表单、分步表单、无障碍、韧性、浏览器、兼容性、安全性和性能 | 无 | 无 |

运行时证据包括：代表性表单状态下的 axe 检查、仅使用键盘的步骤恢复、Chromium/Firefox/WebKit 配置、窄视口溢出检查、每个文档示例的 hydration 检查、可中止的验证和提交、50/200/500 字段预算、bundle 和 tree-shaking 预算、仅使用 registry 的使用方安装，以及格式错误输入/HTML 注入场景。

该概况刻意保持细粒度。表驱动测试可以在一项能力中验证多个值，但单个宽泛的集成测试不能将不相关的功能系列标记为完成。

## 如何维护证据

Profile v3 会统计由客户端负责的推迟和不支持工作，而不是通过宽泛的不适用标签将其隐藏。未来工作应在不削弱分母的前提下深化证据：

- **证据深度，而非布尔值。** 要求每项能力提供相关的单元、一致性、浏览器和隔离使用方证据组合。记录上游规范版本和证据时效性，避免单个测试引用承担所有置信级别。
- **使用方部署矩阵。** 将软件包和 registry 输出安装到全新的 Vite 和服务端渲染 React 应用中，然后验证生产构建、hydration、客户端边界以及受支持的 React 和框架版本。
- **Schema 演进和草稿。** 将新的顶层未知字段保留扩展到嵌套编辑，然后覆盖字段重命名、移动和移除、未知枚举值、版本偏差，以及不会静默丢失数据的分阶段 v1 桥接升级。
- **安全性和抗误用能力。** 为格式错误的描述符、深层嵌套输入、超大集合、CEL 预算耗尽、秘密泄露和软件包来源添加属性测试和模糊测试。
- **网络生命周期和可运维性。** 将已验证的重试和长时间运行操作核心扩展到离线恢复、重连风暴、跨标签页取消和脱敏遥测钩子。
- **人工无障碍验证。** 分别跟踪屏幕阅读器检查、400% 缩放、强制颜色、减少动态效果和触控目标。人工证据保持可见，但不会提高自动化就绪度百分比。
- **高级表单 UX。** 测试远程选项加载、本地化值和消息、草稿自动保存、大型重复字段虚拟化以及跨步骤异步依赖。

## 添加或关闭检查

1. 为该能力添加最小的失败一致性测试或运行时测试。
2. 实现该行为，并使聚焦测试通过。
3. 将 `readiness/profile.ts` 中对应行从 `missing`、`deferred` 或 `unsupported` 更改为 `verified`，并让它指向该测试。
4. 运行 `bun run test:conformance`、所属测试套件和 `bun run readiness:report`。
5. 当上游规范添加新的表单相关功能时，审查分母。

概况变更应像公共兼容性变更一样接受审查：能力 ID 保持稳定，显式添加新要求，移除能力则需要有文档记录的范围决策。
