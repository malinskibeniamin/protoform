Protoform 部署为单个静态产物：

- `/docs` 下的 Blume 文档；
- `/r` 下构建完成的 shadcn 注册表 JSON；
- 由浏览器内 Connect transport 支持的交互式示例。

静态部署不包含应用服务器、账户、数据库，也没有冷启动。书店示例将临时状态保存在浏览器中，并在页面重新加载时重置。

## 使用 Cloudflare Pages 部署

将 `malinskibeniamin/protoform` 导入为 Pages 项目，并使用以下设置：

| 设置 | 值 |
| --- | --- |
| 生产分支 | `main` |
| 构建命令 | `bun run build` |
| 构建输出目录 | `dist` |
| 根目录 | 仓库根目录 |

在 **设置 → 环境变量** 中固定工具链版本：

| 变量 | 值 |
| --- | --- |
| `BUN_VERSION` | `1.3.14` |

每次推送到 `main` 后，Cloudflare 都会重新构建站点。如果 Pages 项目名为 `protoform`，公开端点如下：

```text
https://protoform.pages.dev/docs
https://protoform.pages.dev/r/{name}.json
https://protoform.pages.dev/r/protoform.json
```

配置 shadcn，以便从 Pages 部署安装当前源代码：

```json
{
  "registries": {
    "@protoform": "https://protoform.pages.dev/r/{name}.json"
  }
}
```

```bash
bunx shadcn@latest add @protoform/protoform
```

如果 `protoform.pages.dev` 不可用，请使用 Cloudflare 显示的实际 `*.pages.dev` 主机名。之后也可以通过自定义域名公开相同路径，例如 `https://protoform.dev/docs` 和 `https://protoform.dev/r/{name}.json`。

## 本地验证

```bash
bun install --frozen-lockfile
bun run build
bun run start
```

打开 `http://localhost:8080/docs` 和
`http://localhost:8080/r/protoform.json`。

## 发布源代码快照

托管的 `/r` 端点包含 `main` 中的当前源代码。稳定安装应固定到不可变的 Git 标签：

```text
https://raw.githubusercontent.com/malinskibeniamin/protoform/v1.0.0/public/r/{name}.json
```

`v*` Git 标签必须与 `package.json` 匹配；发布工作流会先运行质量和安全检查，然后创建归档、校验和、来源证明以及 GitHub release。
