shadcn React Hook Form 指南从 Zod 开始。Protoform 保持相同的 UI 结构，但将
schema resolver 替换为 protobuf descriptor。React Hook Form 仍是默认引擎，也是
Protoform 的参考行为。

```bash
bunx shadcn@latest add @protoform/protoform-core
```

```tsx
import { Controller } from "react-hook-form";
import { Button } from "@/components/ui/button";
import { Field, FieldError, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";
import { useProtoForm } from "@/hooks/use-proto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  const form = useProtoForm(SignupRequestSchema, {
    defaultValues: { email: "", displayName: "" },
  });

  return (
    <form onSubmit={form.handleSubmit((values) => console.log(form.createMessage(values)))}>
      <Controller
        control={form.control}
        name="email"
        render={({ field, fieldState }) => (
          <Field data-invalid={fieldState.invalid}>
            <FieldLabel htmlFor={field.name}>Email</FieldLabel>
            <Input {...field} id={field.name} aria-invalid={fieldState.invalid} />
            {fieldState.invalid ? <FieldError errors={[fieldState.error]} /> : null}
          </Field>
        )}
      />
      <Button type="submit">Create account</Button>
    </form>
  );
}
```

## 可获得的功能

- 底层使用 `resolver: createProtoResolver(schema)`。
- 使用 `createMessage(values)` 将表单值转换为 protobuf message。
- 使用 `createUpdateMask()`，仅在更新请求中包含已修改且可写的 protobuf 路径。
- 使用 `setOneofValue(path, case, value)` 安全地更新 oneof。
- 使用 `setServerErrors(error)` 将 Connect/gRPC 字段违规映射回 RHF。

返回值是完整的 `UseFormReturn`，因此现有的 `Controller`、`useFieldArray`、
`watch`、`reset`、resolver 选项以及不常见的 React Hook Form 模式仍然可用。

## 验证部分编辑

更新表单有时会省略服务器仍会保留的字段值，例如只写凭据。启用 `modified-fields`
验证后，只有用户编辑该字段时，省略的值才会被视为无效：

```tsx
const form = useProtoForm(ServiceConnectionSchema, {
  defaultValues: connection,
  validationScope: "modified-fields",
});

const onSubmit = form.handleSubmit(async (values) => {
  await updateConnection(create(UpdateServiceConnectionRequestSchema, {
    connection: form.createMessage(values),
    updateMask: form.createUpdateMask(),
  }));

  form.reset(values);
});
```

修改集合会有意持续保留。如果字段初始为空，随后输入内容又再次清空，Protoform 会验证该
空值，并在更新掩码中包含对应的 protobuf 路径。未触碰的空字段既不会被验证，也不会被
包含。`reset()` 会建立新的编辑基线。消息级 CEL 问题仍然可见，因为 Protoform 无法安全地
将其归因于某一个已修改字段。创建表单仍默认验证完整消息。

## 生成字段

默认 registry item 使用 React Hook Form：

```bash
bunx shadcn@latest add @protoform/protoform-react
```

```tsx
import { AutoForm } from "@/components/auto-form";
import { SignupRequestSchema } from "@/gen/example/v1/signup_pb";

export function SignupForm() {
  return (
    <AutoForm
      schema={SignupRequestSchema}
      formOptions={{ shouldFocusError: true }}
      validationMode="blur"
      revalidationMode="change"
      onFormInit={(form) => {
        // Full React Hook Form API.
        form.watch("email");
      }}
      onSubmit={async (message, form, { updateMask, signal }) => {
        await client.signup(message, { signal });
        console.log(form.formState.isDirty, updateMask?.paths);
      }}
      withSubmit
    />
  );
}
```

`formOptions` 会传递给 `useForm`。`onFormInit`、`onFieldChange` 和 `onSubmit` 接收
原生 React Hook Form 实例。Protoform 在不替换你已熟悉 API 的前提下，增加了生成式渲染。

## 实验性功能：React Hook Form v8 beta

React Hook Form v8 支持是一条独立的可选路径。它不会替代上面的稳定版 v7 item，
而且可以在同一个应用中评估两个版本。上游 API 仍处于 beta 阶段，因此 adapter 固定使用
`8.0.0-beta.3`。

安装实验性原生 hook：

```bash
bunx shadcn@latest add @protoform/use-proto-form-v8
```

```tsx
import { useProtoForm } from "@/hooks/use-proto-form-v8";
```

单独安装实验性生成式表单：

```bash
bunx shadcn@latest add @protoform/auto-form-react-hook-form-v8
```

```tsx
import { AutoForm } from "@/components/auto-form-react-hook-form-v8";
```

这些 item 会通过 `react-hook-form-v8` package alias 安装 v8，并保留原生 v8 API。
在迁移完成之前，请将稳定版和 beta 版的 import 分开。采用 beta 路径前，请查看上游
[v7 到 v8 迁移指南](https://react-hook-form.com/migrate-v7-to-v8)和
[beta.3 发布说明](https://github.com/react-hook-form/react-hook-form/releases/tag/v8.0.0-beta.3)。

需要注意以下 beta 限制：

- `useFieldArray` 公开 `field.key`，并移除 `keyName`。Protoform v8 adapter 已使用 `key`。
- v8 的类型支持扁平基本类型数组，但直接使用 `useFieldArray` 渲染时仍存在上游运行时限制。
  Protoform 测试覆盖了重复基本类型字段的添加、删除和提交；请单独验证自定义 field-array 渲染。
- `Controller` 和 `useController` 现在保留真实 DOM 元素。请将 `field.ref` 转发到 input，
  以确保 focus 和原生验证继续工作。
- 请使用 `subscribe`，不要使用 callback `watch`。替换整个 field array 时请使用 `replace`；
  通过 `setValue` 更新数组的计划移除项尚未进入 beta.3。

已经标准化使用其他表单 store？请参阅
[TanStack Form](/docs/tanstack-form) 中的原生 hook 和生成式 AutoForm 路径，或
[Formik](/docs/formik) 和 [Final Form](/docs/final-form) adapter。
