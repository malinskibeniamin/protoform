title: Deployment
description: Run the docs, public registry, and live bookstore API from one portable container.
---

Protoform needs one deployment, not an npm registry. The production image serves:

- Blume documentation under `/docs`;
- built shadcn registry JSON under `/r`;
- the bookstore ConnectRPC service under `/api`.

The public gateway keeps the browser and RPC API on the same origin. It strips `/api` before
forwarding to the internal Connect server and forwards every other path to Blume.

Set `PUBLIC_ORIGIN` to the external HTTP or HTTPS origin. This keeps forwarded host and protocol
metadata correct behind a TLS-terminating platform proxy. The container health check probes the live
Connect service through `/api/health` and the rendered documentation through `/docs`.

```bash
docker build -f Dockerfile.docs -t protoform .
docker run --rm -p 8080:8080 -e PUBLIC_ORIGIN=http://localhost:8080 protoform
```

Open `http://localhost:8080/docs/bookstore`. The same image can run on any service that accepts an
OCI container and provides a `PORT`; it does not require a specific host or Protoform-owned domain.

## Demo state

The bookstore is intentionally temporary:

- each browser gets a random publisher ID in session storage;
- data is isolated by that parent resource;
- idle libraries expire after 30 minutes;
- the process keeps at most 500 libraries and 20 books per library;
- restarting the deployment resets everything.

There are no accounts and no database. This keeps the flagship demo real enough to exercise all
five RPCs without presenting the in-memory store as an application architecture.

## Release a source snapshot

The hosted `/r` endpoint always contains the deployment's current source. A `v*` Git tag must match
`package.json`; the release workflow then runs the complete quality and security gate before creating
an archive, checksum, provenance attestation, and GitHub release. Consumers can install
`public/r/*.json` through the raw URL for that tag.
